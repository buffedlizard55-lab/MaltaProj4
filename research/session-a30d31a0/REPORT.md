### What PR #260 changes

- **`scripts/publish_root_fallback.py`**
  - New `source_drift(revision, against, root)`. It runs `git diff --name-only` between the build's recorded `revision` and the tree the build would be staged into. This is a tree-to-tree comparison, so it works in a shallow CI checkout.
  - Staging is refused when any **build input** differs.
  - Not counted as build inputs: generated root outputs (`stage_legacy.ALLOWED | EXTRA`), `COORDINATION.md`, `README.md`, and `research/**`, which `scripts.build` links to but never reads.
  - Inside a work tree the check fails closed. A root outside any repository has no committed source to roll back, so it reports no drift.
  - New `--check-drift` CLI: exit 0 = clean, 3 = drift.
- **`.github/workflows/pages.yml`**, root-fallback step only:
  - `scripts.validate` and `unittest` now `return 3`, which fails the step before any push.
  - A pre-push hook re-runs `--check-drift` against the exact remote commit each push would fast-forward. This covers the clean-rebase path, where `git pull --rebase` succeeds over newer source.
- **`tests/test_session_a30d31a0.py`** (15 tests). These run the real step body, extracted from `pages.yml`, against a throwaway bare origin and runner clone. Scenarios:
  - the `dce494b` replay;
  - a clean rebase over newer source;
  - commits that only touch receipts or the board (these must still publish);
  - a failing gate.
  
  Run against the previous step and publisher, three of those scenarios push a rollback. Against the new step none do.

**Why it mattered right then.** Run `40069834693` (push, built from `4a50ea4`, i.e. before #251) was still queued ahead of the newer runs. Three facts made it dangerous:
- Its own pre-refresh gate passes at `4a50ea4`, because that snapshot has no alias-priced row. I checked this.
- Its rebase must conflict on `build-info.json`.
- Its replay does `git checkout -B … origin/main` and *then* runs `python -m scripts.publish_root_fallback`, which loads the module from **`main`'s tree**.

So once #260 was on `main`, that old run's replay refuses instead of rolling #251's stylesheet and build back.

**Operational consequence for other sessions:** a merge that changes build inputs while a run is building supersedes that run's *root* publish. That run still deploys its Pages artifact, and the next run publishes the root.
