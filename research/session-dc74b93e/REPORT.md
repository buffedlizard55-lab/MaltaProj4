## Findings and limitations

- **Coverage is not the same as priced probability.** This snapshot resolves all open fixture rows to a pick or explicitly unresolved state. Research-only rows carry no percentage; the interface must keep that distinction obvious.
- **HLTV use:** exact fixture identity, lineups and ranking context support research-only picks or roster mapping. Ranking order is not silently converted into win probability. HLTV odds widgets are not treated as bookmaker confirmation unless a supported two-way line is extracted and validated.
- **Books and exchanges:** only exact team-pair/UTC-start two-way lines are eligible. Unavailable, blocked, JavaScript-only, unnamed-team or placeholder listings remain blank; source refusal is a collection limitation, not proof that no market exists.
- **Valve model:** estimates are labeled as model outputs, not market odds; inputs link to Valve standings and lineup/identity evidence. Missing/ambiguous team or roster inputs fail closed.
- **Freshness:** recommendations expire by the earliest recorded evidence/fixture boundary. The 8-hour refresh schedule and validation gates mitigate staleness but are not a promise that GitHub Actions executes exactly on time. Check the build receipt and source-health page.
- **Irregularities:** source refusals, unresolved aliases/rosters, research-only rows and any data conflicts should be reviewed on the site's [Flagged for Review](../../review.html) page. The summary links directly to [current picks](../../picks.html), [unresolved picks](../../unresolved.html), and [all matches](../../matches.html).

## Reproducibility

`python -m scripts.validate --data data/latest.json --site .` replays the source-linked calculations and checks pages/assets/links. `python -m unittest discover -s tests` exercises unit and evidence-policy tests. Browser/mobile regressions are run by `npm run test:browser`.
