# Market-ledger correction — session `dedd2e34`, 2026-10-16 04:5x UTC

## What the earlier receipt in this folder claims, and why it is wrong

`market-ledger.json` and `harvest-summary.json` in this directory were produced by run
[38850237836](https://github.com/buffedlizard55-lab/MaltaProj4/actions/runs/38850237836) using
`scripts/harvest_dedd2e34.py` as it stood at commit `14418fa`. In that version the replay step
normalised every published pair with the *bookmaker* formula — invert each decimal odd, then
remove the overround — regardless of what the source actually published.

For a two-outcome exchange market the raw `outcomePrices` are already probabilities summing to 1.
Applying the reciprocal formula to `[a, b]` returns `[1/a, 1/b]` normalised, which is exactly
`[b, a]`: the swap of the true pair. So the ledger reported a large block of rows as
`orientation: swapped order`, and a reader would have concluded that the site publishes the
exchange's prices against the wrong team. **That conclusion was this project's bug, not a defect in
the published board.** No probability on the site was ever affected: `scripts/refresh.py` maps each
outcome by name, `scripts/validate.py` re-derives every displayed percentage from the stored row, and
`verification-c6/audit_snapshot.py` re-joins the raw market independently — both were green on the same
snapshot before and after this change.

## The fix

`scripts/harvest_dedd2e34.py` now records an explicit input mode per row:

- `mode = 'prices'` for an exchange — divide each price by the pair sum;
- `mode = 'odds'` for a bookmaker — take reciprocals, then remove the overround;

plus a `0 < value < 1` guard so an exchange pair can never be fed through the odds branch.
`replay_check()` still tries both orientations and labels which one reproduced the published row,
so an orientation label is a *finding*, never an assertion of error.
